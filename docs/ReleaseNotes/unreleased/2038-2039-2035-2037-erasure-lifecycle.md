## App — the local erasure as one operation per tab, and an end to the cross-tab clearer (PR #2670)

**The erasure and its report now outlive the page that started them (#2038).** Erasing resets the display language first, so the erasure clears what that change saves. In any language other than English, that reset rebuilds the whole page while the erasure is still running. The page used to hold the "working" state and the result itself, so the rebuilt page forgot both. A second erasure could be started over the first one, and the first one's report went to a page that no longer existed, so the user saw no report at all. The erasure is now a single operation for the tab, held outside the page. The rebuilt page shows that it is running, refuses to start a second one, and shows the report when it finishes. A new browser test drives this in Spanish. Against the old code it finds no report.

**A wallet that is still reconnecting is waited for, not misreported (#2039).** When the app restores a wallet connection from a previous visit, there is briefly no real connection to close, only a stored record of one. Closing that record did nothing, and the restore then finished anyway and put the session back. The erasure now waits a bounded few seconds for the restore to finish, then closes whatever is actually connected. If the wait runs out, it says the wallet could not be disconnected yet, that it may sign the user back in, and that erasing again once it has will finish the job. Before, this case was reported as a wallet that refused.

**A wallet connection that reloads the page is closed last, and the report survives the reload (#2035).** Coinbase Wallet's mobile link ends its connection by reloading the page, and the app cannot stop it. That connection is now closed only after everything the erasure counts has been cleared, so the reload can no longer interrupt anything. Just before that last step, the report as it stands is kept for this tab only. It holds counts and outcomes, nothing about the wallet or the user. If the page reloads, the report is shown again and then discarded. That wallet's library can fire its reload a moment after it reports the connection closed, so the kept copy is not removed the instant the step finishes: it lasts thirty seconds, and is removed when that time runs out, when the report is dismissed, by the next erasure, or when it is read after a reload. It is the erasure's own record, so it is never counted as an item the erasure failed to remove. After a reload, the report says only what is known: the step ran last and the page reloaded during it or shortly after it. It does not claim the wallet was disconnected, and it tells the user how to check.

**Other open tabs no longer clear the stores they share with the erasing tab (#2037).** Another tab told about an erasure used to clear the shared browser storage and the wallet databases again after closing its own wallet. That second, uncoordinated clearer had two failures that could not be fixed inside the design. Arriving late (a background tab can receive the request long after it was sent), it deleted things the user had stored since, sessions included. Arriving early, it emptied the wallet databases before the erasing tab had counted them, so that tab reported erasing nothing over records it had removed. Other tabs now act only on their own per-tab data, their own wallet connection and their on-screen preferences. Their language reset removes exactly what it wrote and nothing else, and it keeps a language the user chose since; theme and mode now follow the same rule, so a tab that hears of the erasure late shows a theme or mode chosen since rather than the default. A tab never runs its own erasure and a follow-up of another tab's side by side: a request from another tab that arrives during this tab's own erasure is left to it, and an erasure requested while this tab is still closing its wallet for another tab waits for that first (for up to thirty seconds after a wallet that reloads the page, since its reload can come late), so that reload cannot cut an erasure off before its report is kept.

**The erasure ends exactly the connections the request found.** It decides which wallets to close from the live connections once any restore has settled, and closes only those, so a wallet the user connects while the erasure runs is left alone. A wallet that is still connected while the user is part-way through connecting another is now closed too; the erasure used to skip it. And a close that finds nothing left to end is no longer reported as having signed the user out. The cost is that a wallet closing in another tab can write a small connection record back after the erasing tab has finished. The Data Rights page now states this, along with the remedy: erasing again from any tab removes it.

Closes #2038. Closes #2039. Closes #2035. Closes #2037.
