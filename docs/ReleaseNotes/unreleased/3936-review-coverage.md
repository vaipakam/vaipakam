## Local testing — tooling for the review coverage pass (PR #TBD)

The review coverage pass (ReviewCoveragePassDesign) now has its tooling. Every declaration under contracts/src gets a hash of its text with comments and spacing removed. A function moved to another file keeps its coverage, a comment-only edit keeps it, and one changed operator loses it. The ledger (contracts/review-coverage/ledger.json) records, per hash, four marks as opaque review numbers: the reader pass, the reviewer loop, the specification mark and the cross review. A declaration counts as covered only with all four. The ledger holds no findings.

One command prints the coverage report: the share of declaration code with all four marks and the share carrying each mark, per area and per file, and each uncovered declaration by name. Vendor code, the storage-layout probes and interfaces are excluded, each with its reason. The governance launch check reads the same report as JSON.

The entry check refuses a ledger entry whose hash is not a declaration at the commit it names. It also refuses a reader mark recorded by the thread that wrote the fix under review, a cross review made by the thread that made the first reader pass, and a new reviewer mark while the latest planted-fault run has a miss. In a shallow checkout it fetches the one commit an entry names before checking it. It runs in the pre-deploy gate and fails it. The report prints beside it as a warning until the audit freeze.

The unit tool lists, for a facet or a standalone contract, the declarations it owns plus the library functions its code reaches. It leaves out what is already covered and the shared libraries, which are reviewed in their own slices. Over the size limit it splits into slices of whole declarations, and it describes each one with its lines, what it calls outside the unit (including calls through the Diamond) and who calls it. The size ladder steps the limit down after a planted-fault miss. It steps up only on planted-fault runs at the next size that are caught in full and include a missing-rule fault. The first such run makes the new size provisional. A second confirms it once the two runs between them cover all five lenses and all three depths.

The rest connects to the private review repository. The tool makes the two branches of a review-only pull request, finding each declaration again in the head when a fix has been merged on top (a fix from this repository is carried across as a change against the commit the copy was made from, the workflow files left out), checking that the head restores exactly the reviewed tree, and holding the size limit on that tree, and refuses one whose head or base differs from the pinned commit by more than the unit. A slice larger than one review unit is refused by name, since a single struct or function cannot yet be split (#4008). It writes the pull request's description itself, from a workspace whose sources it first checks are the head's byte for byte, the slice plus the cross-cutting rules checklist, and refuses a hand-written one that differs. It never opens one against main, and it cleans up branches. The one-way copy to the review repository refuses while that repository's workflows are enabled. It leaves out the workflow files and the dependency-update config, and checks that the copy differs from the pinned commit by exactly those paths. The review repository itself is an owner step that is not done yet.

The reports tool (#3914) and this one now follow self-calls through the Diamond by one shared rule.

Closes #3936.
