## Thread — keeper backstop for returning reward VPFI to Base (PR #<n>)

Reward VPFI that a mirror holds for Base moves home only when someone makes a permissionless call and pays its cross-chain fee. The same is true of the messages that let Base release what it reserved. Nothing made those calls on a schedule, so an issued repatriation could sit untravelled, a cancelled one could keep Base's availability reserved, and quarantined compensation or a retired mirror's pending surplus could stay on the mirror until someone acted by hand. The keeper now has a return-transport duty. It runs hourly and ships switched off, behind its own arming flag.

For each repatriation authorization that Base holds pending, the keeper sends the instruction to the mirror. On the mirror it executes a recorded instruction once the outbound lane can carry the whole amount, which sends the VPFI home. For an instruction the administrator cancelled, it sends the cancellation acknowledgement so Base can release the amount. The keeper never issues or cancels an authorization; those stay with the administrator. Each instruction and acknowledgement is sent once. One that has not landed within a day is announced to operators rather than paid for again, because a failed cross-chain message stays on its destination for manual re-execution.

On a mirror the keeper also returns each quarantined compensation, and on a retired chain the pending surplus, in parts. Each part is bounded by the sending chain's outbound lane and by the receiving chain's inbound capacity. A part too small to be worth its fee waits, unless it is the last. Every send that moves VPFI is announced to operators with its amount and transaction. Fees are held to the duty's own ceiling, `REWARD_RETURN_TRANSPORT_MAX_FEE_WEI`, and the smallest part is set by `REWARD_RETURN_MIN_PART`. The return-sender contract's ABI is now exported with the rest, so off-chain code can quote its fees. Refs #2984.

> Caveat: ships disarmed. Arming it on any chain is a separate owner decision.
> Caveat: the duty finds its work in the indexer's event record. An authorization or quarantine the indexer has not recorded is not seen until it is, and the record is read up to 2,000 rows per kind and chain, past which the run says it did not read further.
