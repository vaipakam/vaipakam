## Keeper — reward days now close, finalize and broadcast by themselves (PR #2616)

The cross-chain interaction-reward cycle needs three permissionless calls every UTC day: each chain reports the day's interest (`closeDay`), Base finalizes the day once every expected chain has reported or the grace window has run out (`finalizeDay`), and Base broadcasts the finalized totals back to the mirrors (`broadcastGlobal`). Until now nothing made those calls on a live chain. The keeper's simulations made them by hand, so a launched reward programme would have sat with every day open: mirrors unreported, nothing finalized, nothing for the remit pass to fund, and nothing mirror users could claim.

A new keeper pass, `rewardDayClose`, makes them. It runs every 15 minutes and works the last 14 elapsed days on every reward chain. On a mirror it pays the messenger's own quote for the report fee (the messenger refunds any unused part), and it does not send a report for a day Base has already finalized, because Base would refuse it. On Base it judges "every expected chain has reported" chain by chain, not by counting reports, so it never finalizes a day while a listed chain's report is still inside grace. It refuses to finalize against an empty expected-source list, and it says so when the list leaves Base out, since Base's own interest then reaches no day's total. It confirms each broadcast by reading the mirrors it serves, flags one still missing after two hours, and re-sends after six to the mirrors still lacking it only, so a lane that delivered is not paid for again. It also says when an expected mirror is missing from the broadcast destinations, since that mirror's users could never claim. Every write is simulated first. Each refusal, a missing chain in the last hour of grace (the last quarter of a shorter grace), and a day finalized at grace without a chain (named from the finalization's own events) are posted to the ops channel. The only state the pass keeps is each broadcast's send time, in the keeper's private work queue, so it needs no new migration. The reward messenger's ABI is now exported as a standalone contract, so the keeper prices fees from compiled ABIs rather than hand-typed ones.

The pass ships switched off, behind `REWARD_DAY_CLOSE_ENABLED` (on top of `KEEPER_ENABLED`), and needs the owner's OK to arm. The two-chain Anvil simulation now runs the daily close through this pass instead of making the calls itself. Closes #2612.
