## Keeper — reward days now close, finalize and broadcast by themselves (PR #2616)

The cross-chain interaction-reward cycle needs three permissionless calls every UTC day: each chain reports the day's interest (`closeDay`), Base finalizes the day once every expected chain has reported or the grace window has run out (`finalizeDay`), and Base broadcasts the finalized totals back to the mirrors (`broadcastGlobal`). Until now nothing made those calls on a live chain. The keeper's simulations made them by hand, so a launched reward programme would have sat with every day open: mirrors unreported, nothing finalized, nothing for the remit pass to fund, and nothing mirror users could claim.

A new keeper pass, `rewardDayClose`, makes them. It runs every 15 minutes on every reward chain and works every elapsed day not yet worked through, however late it is first armed or however long the keeper is down, plus at least the last 14 days. It closes no day on a mirror whose reward clock starts at a different moment from Base's, and Base finalizes no day while a listed mirror it can read runs another clock, since a day number has to cover the same hours everywhere. On a mirror it pays the messenger's own quote for the report fee (the messenger refunds any unused part), and it still sends a report for a day Base has already finalized: Base drops that report's day figures but keeps the chain-wide figures it carries, which a mirror's last report must not lose. A mirror also says when it is missing from Base's expected-source list, because Base then refuses every report it sends, chain-wide figures included; a refused report can be executed again by hand once the chain is listed again, and #2618 tracks letting a detaching chain's last report through. A mirror whose messenger can only send an older report shape does not send one for a day Base has finalized, since Base would refuse it after the fee is paid, and says so. On Base it judges "every expected chain has reported" chain by chain, not by counting reports, so it never finalizes a day while a listed chain's report is still inside grace. It refuses to finalize against an empty expected-source list or one that leaves Base out (Base's own interest would then reach no day's total), and says so. It confirms each broadcast by reading the mirrors it serves, flags one still missing after two hours, and re-sends after six to the mirrors still lacking it only, so a lane that delivered is not paid for again. Each mirror is judged against its own last send, so a mirror added to the destination list after a day went out is sent that day on its own, and a late mirror stays flagged in the run that re-sends to it until it is read holding the day. A mirror taken off the destination list after a broadcast that never reached it, or an expected mirror never put on it, is still checked and sent the day on its own, and if the Diamond will not send to it alone the pass says that mirror cannot be reached and keeps the day in view until it can be sent; a mirror off the list with no standing in the day is owed nothing. A Base day an admin finalized before Base closed it no longer waits on a close that can never happen, and a window held open by a stuck day is read in bounded slices, so it never stops newer days from being worked. A broadcast whose receipt the keeper did not see counts as sent, so it is never paid for twice inside the re-send interval, while one the node refused outright (insufficient funds, say) is not, and a mirror the keeper cannot read is reported as unknown rather than assumed delivered or re-sent to blind. A destination list that cannot be read stops only the broadcast, never finalization, and is reported until it reads. It also says when Base's expected-source list and the broadcast destinations disagree, either way, since a mirror missing from one or the other either never receives a finalized day or has its reports refused, and when Base itself or a repeated mirror is among the destinations, each of which pays for a useless message every day. Every write is simulated first, and a call the RPC gave no answer about is never reported as the contract's refusal. Each refusal, a missing chain in the last hour of grace (the last quarter of a shorter grace), and a day finalized without a chain are posted to the ops channel. The last is posted once, whoever finalized the day, and names the chains read from Base's own record of the day. The only state the pass keeps is the oldest day it has not yet worked through on each chain and, for each broadcast day, every destination it has had with the last send that covered it, and each finalized day's zeroed chains with whether that notice was delivered, in the keeper's private work queue, so it needs no new migration. The reward messenger's ABI is now exported as a standalone contract, so the keeper prices fees from compiled ABIs rather than hand-typed ones.

The pass ships switched off, behind `REWARD_DAY_CLOSE_ENABLED` (on top of `KEEPER_ENABLED`), and needs the owner's OK to arm. The two-chain Anvil simulation now runs the daily close through this pass instead of making the calls itself. Closes #2612.
