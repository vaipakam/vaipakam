## Keeper — reward days now close, finalize and broadcast by themselves (PR #2616)

The cross-chain interaction-reward cycle needs three permissionless calls every UTC day: each chain reports the day's interest (`closeDay`), Base finalizes the day once every expected chain has reported or the grace window has run out (`finalizeDay`), and Base broadcasts the finalized totals back to the mirrors (`broadcastGlobal`). Until now nothing made those calls on a live chain. The keeper's simulations made them by hand, so a launched reward programme would have sat with every day open: mirrors unreported, nothing finalized, nothing for the remit pass to fund, and nothing mirror users could claim.

A new keeper pass, `rewardDayClose`, makes them. It runs every 15 minutes and works the last 14 elapsed days on every reward chain. On a mirror it pays the messenger's own quote for the report fee (the messenger refunds any unused part), and it still sends a report for a day Base has already finalized: Base drops that report's day figures but keeps the chain-wide figures it carries, which a mirror's last report must not lose. On Base it judges "every expected chain has reported" chain by chain, not by counting reports, so it never finalizes a day while a listed chain's report is still inside grace. It refuses to finalize against an empty expected-source list or one that leaves Base out (Base's own interest would then reach no day's total), and says so. It confirms each broadcast by reading the mirrors it serves, flags one still missing after two hours, and re-sends after six to the mirrors still lacking it only, so a lane that delivered is not paid for again. A mirror taken off the destination list after a broadcast that never reached it is still checked and re-sent to on its own, and if the Diamond will not send to it alone the pass says that mirror cannot be reached. A broadcast whose receipt the keeper did not see counts as sent, so it is never paid for twice inside the re-send interval, and a mirror the keeper cannot read is reported as unknown rather than assumed delivered or re-sent to blind. A destination list that cannot be read stops only the broadcast, never finalization, and is reported until it reads. It also says when Base's expected-source list and the broadcast destinations disagree, either way, since a mirror missing from one or the other either never receives a finalized day or has its reports refused, and when Base itself or a repeated mirror is among the destinations, each of which pays for a useless message every day. Every write is simulated first, and a call the RPC gave no answer about is never reported as the contract's refusal. Each refusal, a missing chain in the last hour of grace (the last quarter of a shorter grace), and a day finalized without a chain are posted to the ops channel. The last is posted once, whoever finalized the day, and names the chains read from Base's own record of the day. The only state the pass keeps is each broadcast's send time and the destinations the day has had, and each finalized day's zeroed chains with whether that notice was delivered, in the keeper's private work queue, so it needs no new migration. The reward messenger's ABI is now exported as a standalone contract, so the keeper prices fees from compiled ABIs rather than hand-typed ones.

The pass ships switched off, behind `REWARD_DAY_CLOSE_ENABLED` (on top of `KEEPER_ENABLED`), and needs the owner's OK to arm. The two-chain Anvil simulation now runs the daily close through this pass instead of making the calls itself. Closes #2612.
