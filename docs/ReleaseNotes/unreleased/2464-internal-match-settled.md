## Indexer — internally matched loans now show as settled once claimed (#2464)

When both sides of an internally matched loan have claimed, the protocol settles it. The indexer kept showing these loans as internally matched anyway, so the loan page, Positions and the desk read as if claims were still pending. The handler for the protocol's settlement event only accepted a hand-written list of earlier states (repaid, defaulted, liquidated) and left internally matched loans out. Meanwhile the handler for general status changes deliberately leaves this step to the settlement event, so nothing ever corrected the row. On Base Sepolia, loans 24–27 were stuck this way.

The indexer now treats the protocol's settlement event as authoritative: it settles a loan whatever state the loan was in. It no longer keeps a second copy of the contract's rules about where settlement can come from. Loans already stuck this way are settled by a check that runs on every indexer pass, not by a one-time migration. It settles a loan only where the indexer's own event log holds the protocol's settlement for it. It dates each settlement by reading that event's block from the chain again, because the time stored in the log can be the indexer's clock when the original read failed. If that read fails, the loan is still settled, with its time recorded as unknown rather than guessed, so a block the node won't serve can't hold up the others. The indexer's general correction pass stands aside for these loans, so it never settles one first without its event's time. Running every pass also covers a settlement that the previous indexer version logs during a deploy without updating the loan, which a one-time migration would miss.

When the time of a settlement cannot be read during a scan, the loan is settled with its time recorded as unknown, and a later replay of the same block fills it in. The "we found this by checking" notice from the indexer's own correction pass can no longer be attached to a settlement the event wrote.

Closes #2464.
