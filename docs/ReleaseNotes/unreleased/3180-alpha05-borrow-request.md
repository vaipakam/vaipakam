# The next app can post a borrow request: your own amount, rate and term, with the protocol's own verdict before you sign

When no lender offer fits, a borrower on the next app's Borrow page can now post their own request for the pair instead. The form asks for the exact amount, the collateral (with a Max button for the whole wallet balance), the yearly rate, the term, how long the request stays open, how interest is charged if the loan is repaid early, and whether partial repayments are allowed. Every figure is read exactly as typed: more decimals than the token has, a rate above 100% or two decimals, or a term beyond the longest one the network allows are each refused in place with the fix, never rounded. The terms offered are only those the protocol has open, read from it, and a term can also be typed in days. A live line shows what the borrower would receive at least and owe at the due date if a lender took it now. On a phone that line and the Review button rest just above the bottom bar, full width, where the thumb reaches.

The review is the protocol's own answer to the request, asked as a dry run from the borrower's wallet, so every rule the protocol applies when a request is posted is in it without the app restating any of them. It shows what is locked in the vault now (the vault is opened in the same transaction if needed), the amount asked, that it is filled whole by one lender or not at all, the rate, the due date counted from when a lender takes it, the grace period, what arrives in the wallet when a lender takes it and the fee rule behind it (the list rate, which the borrower's discount tier at that moment can only lower), what is owed at the due date, every lifecycle term the request binds, even the defaults, when it lapses, the loan-to-value at today's prices, and whether a token approval is needed. The consequences say plainly that the collateral stays locked while the request is open and can be taken back by cancelling from five minutes after posting, that a lapsed request can no longer be taken but its collateral stays in the vault until the borrower or anyone closes it and then returns only to the borrower's wallet, that a lender who takes it opens the loan at once without asking again, and the usual default, liquidation and interest commitments. A wallet that does not hold the collateral is told by how much and cannot confirm; the review is read again each block while it is open.

Posting takes an approval for exactly the collateral when the wallet's current approval does not cover it, and then the request itself. Before the approval the protocol's dry run can only get as far as pulling the collateral, so a stop there is named as the approval's to clear, and only an error the protocol names counts as a refusal; after the approval the request is dry-run again and sent only if the protocol would accept it. If anything stops it after an approval, the app asks to put the approval back and says whether that happened. The outcome is measured from the transaction's own logs: the request the protocol recorded for this wallet, and the collateral that moved into the vault. The finish card links to the Offers page, where the request can be followed and cancelled.

The approval steps that taking an offer and posting a request share now live in one module, so the two flows cannot drift apart on how an approval is judged, reported or put back. Buttons gain a hover state across the app.

NFT collateral, pair consents and the Advanced options (ranges, fill modes, interest schedules) come in the next Borrow update. The user guide's Basic and Advanced editions gain sections on posting a request in every language.
