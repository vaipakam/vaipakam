## Thread — Keeper: a health factor that cannot exist is not an error (PR #2514)

The keeper's health-factor watcher now tells the protocol's own states apart from real failures, using the same rule as the liquidator. An illiquid loan has no health factor by design, because it has no oracle. The watcher used to log that as an error on every tick, and now skips it quietly, as the liquidator already did. A loan whose asset has no price feed cannot have its health factor computed right now. The watcher now names that as a warning ("an asset this loan needs has no price feed"), not as an undecoded revert, because the subscriber's band alerts for that loan cannot be evaluated. Every other failure is still logged as an error. Found on the first disarmed tick of the keeper on its always-on machine, where both states logged as errors and made a clean tick impossible to certify.
