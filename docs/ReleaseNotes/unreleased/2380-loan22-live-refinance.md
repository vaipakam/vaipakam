## Thread — A real illiquid-collateral loan refinanced through the live app; indexer ingest restored (PR #TBD)

Loan 22 on Base Sepolia was refinanced end to end through app.vaipakam.com on 5 October, using the dev test wallets. That loan is backed by illiquid collateral that both parties consented to, and it is the loan whose refinance used to fail (#2380). The borrower posted the refinance request from the loan's page (request #45, 12% for 30 days). A different lender funded it through the app's own review-and-sign steps. Loan 22 closed as repaid, and loan 23 opened for the same borrower, on the same collateral, still marked illiquid with both parties' consent recorded. The borrower's collateral never left the lien: their wallet balance of the collateral token did not move. All five transactions succeeded. The drive is committed as a reusable live check, and a rerun against loan 22 now stops before sending anything because the loan is closed.

The drive turned up two things, each filed. First, the lender's review never says the request is a refinance: it does not mention that accepting also pays off and closes the borrower's existing loan, and it describes the carried-over collateral as newly locked (#2421). Second, the production indexer had stopped advancing at 05:35 UTC. The merge that added the offer collateral-range columns was published automatically without its database migration being applied, and the safety check added the same day correctly held all indexing until the schema caught up. The two pending migrations, both of which only add columns, were applied by hand at 09:02 UTC, which by the check's design lets indexing resume on its next scan with no redeploy. Until then, today's new offers and loans were missing from the app's lists. Making the automatic deploy apply migrations first, and alerting when indexing pauses, is tracked in #2420.
