## App — a refinance request says what it is, to the lender and to the borrower (PR #2668)

**A lender funding a refinance request is now told it is one (#2421).** A borrow request can be tagged with a running loan it asks to refinance. Accepting such a request does more than open a loan: in the same transaction it pays off and closes the borrower's running loan, with that loan's lender paid from the borrower's wallet. The new lender's loan, less the borrower's loan-initiation fee, is delivered to that same wallet first, so it can fund part or all of the payoff, with the borrower covering any difference. The guided review did not say so. It described the collateral as "They lock 100 tCOL" even when that collateral was already locked under the running loan and simply carried over. The review now names the loan being refinanced, says that accepting pays off and closes it, and says how that payoff is funded. It also describes the collateral from the request's own recorded decision: either the stake already locked under that loan carries over and is not a new pledge, or the borrower pledged a new batch and gets the old loan's collateral back when it closes. The app reads this from the chain. Until it knows, the review says it is checking, or that the check failed with a retry, and it cannot be signed. The running loan can change after a request is posted: it can be repaid or closed, or have collateral added, which breaks a carry-over request. So the review also runs the protocol's own acceptance check for the request, confirms it is the loan's currently recorded request (the only one that can be taken), repeats it while the review stays open, and runs it once more just before signing. If a repeat fails, the review goes back to "check failed" with a retry instead of showing the last answer as current. A request cancelled while its review is open is shown as one that cannot be taken, not as an ordinary borrow request. When that check refuses, the review says the request cannot be taken right now, gives the reason, shows no receipt and offers nothing to sign. On a deployment without that check, the review says it cannot confirm the request is still takeable, and that a stale request fails on-chain with only the network fee spent. The offer list inside the guided flow now tags a refinance request the same way the Offer Book does.

**A borrower posting a refinance request is told it is not a guarantee (#544).** Posting a request changes nothing about the loan until a lender accepts it. The refinance form, its review and the standing request card (including while it is still checking the request's state) now say so: the loan keeps its due date and grace window, it can still default if no lender accepts in time, and the borrower should be ready to repay it themselves.

Closes #2421. Closes #544.
