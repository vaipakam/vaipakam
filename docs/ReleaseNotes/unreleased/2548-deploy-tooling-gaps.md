## Thread — six deploy-tooling gaps from the end-of-programme redeploys, closed (#2548)

The fresh redeploy of Base Sepolia and Arbitrum Sepolia on 2026-10-17 and of BNB testnet on 2026-10-18 hit six gaps in the deploy scripts. Each was worked around by hand at the time. This change closes them so the next fresh deploy needs none of those manual steps.

**The post-deploy sentinel checks verify something again.** The verify and health steps of all three deploy scripts read two counters that no facet exposes any more. Every run printed a question mark for them and passed. The reads now live in one shared list that all three scripts use, and they name the counters the Diamond actually serves (active offers and active loans). A read that cannot be answered now fails the step instead of printing a question mark. That covers a Diamond that is not cut, not deployed, or not on the chain the RPC serves.

**A killed deploy can no longer leave a fake retired Diamond in the record.** A deploy run's simulation writes the chain's deployment file before anything is broadcast. Killing the run between the two leaves a file naming addresses that were never deployed. The next fresh deploy used to record that address as a retired Diamond in the committed archive inventory, and since the indexer's deployment epochs the indexer takes its retired Diamonds from that inventory. The scripts now check that the recorded Diamond has code on the chain before recording it. If it has none, they stop, record nothing, and print the recovery steps. An RPC that cannot answer is also a refusal, because the record must not claim a Diamond it cannot prove exists.

**The CCIP lane list can live in the operator's settings file.** The list of chains a chain is wired to differs per chain: the hub lists every spoke, and each spoke lists the hub. Until now it could only be typed on the command line for each wiring run. It now resolves per chain, the way the router and the token registries already do. A value typed for one run still works as an override. If the per-chain setting and the typed value disagree, the run is refused rather than guessing which topology was meant.

**The faucet mock rig and the oracle configuration no longer overwrite each other.** On the Base and Arbitrum testnets, the only workable liquidation route is the faucet mock rig's swap adapter, because neither chain has a usable real venue. The rig and the oracle configuration step both set the oracle's feed registry, factory, ETH price feed and WETH, so the rig had to run a second time after configuration to restore its settings. There is now a dedicated testnet-mocks phase that runs before configuration. The configuration step adopts the rig's recorded settings instead of the chain's real feeds. It does that only on a testnet, and only after confirming against the chain that the recorded factory really holds the rig's pool for the recorded WETH, so an inconsistent record is refused rather than half-applied. One pass is now enough. Chains with a real venue, such as BNB testnet with PancakeSwap, are unaffected.

**A failed facet count no longer passes verify.** The facet-count check in all three scripts printed "all 0 expected facets registered" and passed when its single read of the Diamond's facet list failed, which happened once on BNB testnet. The failed count produced two values instead of one, so the comparison errored instead of failing. The count now comes from one shared helper that returns a single number or refuses, and a refusal fails the step.

**The gas price can be pinned per chain, and is on BNB testnet.** Forge estimated a 1-wei gas price for one BNB testnet transaction, below the node's minimum, so the transaction never mined and the deploy hung until it was replaced by hand. Each chain can now carry a pinned gas price in the operator settings, BNB testnet defaults to 1 gwei when none is set, and a price given for the run still takes precedence.

Closes #2548.
