## Thread — The keeper closes out loans past their grace period (PR #<n>)

The keeper has a new pass, `graceDefault`, that calls the permissionless time-based default on loans whose grace period has ended. Until now only health-factor liquidations ran automatically, so a past-grace loan stayed open until the lender pressed the close-out button on its page. With the pass armed, a lender who never opens the app is closed out and only has to claim. The pass runs every five minutes. Each run looks at one network and a bounded slice of its open loans, and attempts one loan, because every attempt costs a quote round, a simulation and a send against a per-run request allowance the keeper's other duties share. Networks take turns and the selection rotates, so a loan which cannot be closed does not hold up the rest, and a backlog of past-grace loans is worked through one run at a time. Each run also has a hard cap of 40 outbound requests, counting reads, quotes and the send. A run that reaches the cap stops before sending and logs that it did. The pass's cost therefore cannot grow with the length of governance's swap-venue list. A very long list stops the pass from completing an attempt until #2488 makes that read cheaper. A loan that is also below the health-factor line is left wholly to the health-factor liquidation, so no loan has two automatic closers; a collapsed one that no venue will quote is therefore still closed by the lender's card for now (#2487).

It follows the same rules as the lender's close-out card. It skips a loan whose lender position has an accepted sale, or whose sale state the chain does not establish, because closing it would strand the buyer's payment. For liquid collateral it sends a quoted swap route built by the same route builder the app uses. It previews the call and does not send a route that the chain shows would fall into the full-collateral fallback. It does not send while an earlier keeper transaction on that network is still unconfirmed, so a slow close-out is not sent twice. Just before sending it checks, at one fresh block, that the loan is still above the health-factor line, that the sale state still allows the close, that the collateral amount still matches the quote, and that the previewed route still ends in a sale rather than the fallback. Every loan it passes over is logged with the reason. The sale check now lives in the shared library and is used by both the app and the keeper, so the two cannot drift.

The pass ships dark. It needs its own `GRACE_DEFAULT_ENABLED` secret on top of `KEEPER_ENABLED`, and arming it on the live Worker is a separate owner decision. A loan with no working swap venue still stays open, and the lender's grace-over banner still has to be corrected to say what actually happens (#2484). Closes #2483.
