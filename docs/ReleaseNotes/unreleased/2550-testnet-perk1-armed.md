## Thread — the priority-routing perk is armed on Base Sepolia and Arbitrum Sepolia (PR #2589)

Since 2026-10-19 a lender on Base Sepolia or Arbitrum Sepolia can buy priority-routing credits at 2 VPFI each, paid from their vault. A credit is used only when the solver's fill capacity would refuse the fill. That capacity is the solver's free allowance, raised by any refundable deposit the solver has posted. If the lender has opted that standing intent in and holds a credit, the fill still goes through and uses up exactly one credit. Every other fill is charged to the solver's capacity as before, and no credit moves. Setting the price was also the one-time arming of the effect, which the contracts require before any credit can be sold or spent.

It was set only after the design's two remaining preconditions held on each chain. The keeper change that keeps scanning past a spent fill capacity for credit-backed intents was live there. A new fork test then passed against each chain's deployed Diamond, using its live capacity curve, its live intent switches and its live prices, with no change except the arming itself. On a fork, the test arms the perk and buys a credit. It confirms that a fill the solver can afford uses no credit. With the solver's capacity spent, it confirms that an intent which has not opted in is refused, that the opted-in intent is filled on its one credit, and that the same intent is refused again once the credit is gone.

BNB testnet stays unpriced. Its deployment has no oracle-priced test assets, so no lender intent can be filled there, and a credit sold there could never be used. It will be priced once a fillable pair exists and the same check passes. Each chain's deployment record carries the arming transaction.

The full regression runner now decides which fork tests to run from the fork addresses each test names, rather than from its file name. A test is run when any of its chains' addresses is set, so an Arbitrum-only run now runs the Arbitrum half of the new proof instead of skipping it. A fork test that names no address stops the run instead of being silently dropped. Refs #2550, #1219.
