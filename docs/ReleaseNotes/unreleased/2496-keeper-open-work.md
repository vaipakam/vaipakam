## Thread — the delivery-proof and late-acknowledgement passes, on an open-work queue (PR #2497 re-cut, 2 of 3)

**Two passes land.** The delivery-proof pass indexes each mirror delivery's epoch days and proves the day list of each delivery that holds no epoch, so a mirror's funded days stop being gated. The acknowledgement pass now also acknowledges a released remittance whose delivery landed after all, so the canonical chain resolves the share it had counted as stranded. Both ship disarmed: the delivery-proof pass behind its own flag, and the late acknowledgements behind the existing remittance flag.

**Work is kept until the chain says it is done.** Both passes find their work in the shared event log. Each walks the log forward a page at a time, never past what the indexer has fully recorded, and keeps every item still open in a private queue. An item leaves the queue only when the chain shows it finished, never because it aged out of a window or a count. An item that can never finish takes one row and holds nothing else back, and neither read grows with history. Earlier versions read only the last 45 days of deliveries, or the newest 50 releases, so older work could drop out unseen.

**Every run stays inside its own slot.** Each pass now gets a deadline: its scheduled minute plus its own cadence. Both passes reach the chain only through clients that refuse every read once that deadline has passed, and neither starts a send after it, so whatever is left waits for the next run. The delivery-proof pass handles its chains side by side. A failed batch read in either pass's work queue costs one request and leaves its items for the next run, instead of falling back to one request per item. An item that could not be read keeps its place in the rotation, and an unread on-chain state is never taken as "not done". Items take their turn by when they were last tried, so a few old ones cannot hold back newer ones. Ordinary pending acknowledgements go before the late-delivery backlog. A failure in the late step does not stop that tick's ordinary acknowledgements.

**A packet's reservation is read where the packet says it came from.** The delivery-proof pass reads a packet's reservation on the chain and contract the packet itself names as its sender, not on whichever Diamond is configured today. A wrong source cannot pass anyway, because the rebuilt list must match the packet's own root. Refs #2496, #1944, #1461.
