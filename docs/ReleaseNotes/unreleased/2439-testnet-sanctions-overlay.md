## Thread — a testnet sanctions test list, a script that configures it, and a banner that says why a wallet is flagged (PR #2442)

Until now no script set a Diamond's sanctions oracle on any chain; the step was done by hand or not at all, and on Base Sepolia it had not been done. This adds a configure script. It was first written to point mainnets at Chainalysis's on-chain sanctions oracle, but Chainalysis has retired that oracle: its documentation now says it is no longer supported or maintained, was last updated on 18 March 2026, and is not recommended for production screening. The contracts still answer every read, so nothing on-chain shows that the list stopped growing, and an address designated since then passes every check that reads it. The script therefore refuses every mainnet, including the ones where the retired oracle still answers, rather than install a frozen list as if it were live screening. Which supported source a mainnet uses is an open decision, tracked in #2443.

On a test network the script installs a new testnet-only contract, a sanctions test list, as the whole screen. Before this, no wallet we control could be flagged on a live deployment, so the paths that run only for a flagged wallet could not be exercised: the warning, the blocked actions, the close-outs that stay open, and the frozen-proceeds handling. Only the network's admin can flag or clear an address, every change is logged as an event, ownership moves in two steps, and the contract refuses to be created on any chain that is not on an explicit testnet list. The contract can also extend another sanctions list and pass that list's failures through unchanged, but the script deploys it extending none. A second run reuses the recorded test list only while it extends nothing, the network's admin owns it, and no ownership transfer is pending, so its flags are kept. On a Diamond owned by a timelock the script leaves the oracle as it was and prints the call to schedule; it still deploys and records the test list that call names, so the scheduled call never points at an address with nothing behind it. The configured oracle is written into the chain's deployment record as one entry, replaced whole on each run, and only once the Diamond actually uses it. A dry run writes nothing, and the script follows the same local-only rule for skipping the deployment record as every other deploy step.

The app's flagged-wallet banner now says why the wallet is flagged, and so whom to contact. Its last line used to tell every flagged user to contact Chainalysis. It now reads the configured oracle and names one of: this test network's own test list (contact its operator); the test list and the list it extends (removing it from the test list would not clear the other flag); the test list, with the other list unreadable; the sanctions list the deployment screens against (contact that list's provider); or, when no list flags the wallet itself, the sender it declared while recovering tokens (the flag lifts on its own if that sender is delisted). Both the wallet and its declared sender are read every time and judged the same way, so a flag that comes from the sender also names which list flags the sender and whom to contact. A wallet that is listed itself and whose declared sender is flagged too is told both, since clearing either alone would leave it flagged. A failed read of one never hides what is known of the other, and the banner says what it could not check rather than asserting it. It names no provider, because the Diamond accepts any address as its oracle and a provider cannot be inferred from it. The banner's title and first line now say the wallet is flagged rather than listed, since in the last case the wallet itself is not on any list. When the reason cannot be read, or at the moment it is read nothing flags the wallet any more, it names no contact and asks for a reload. Every read is taken at one block and repeated every 30 seconds while the banner is shown, so a flag added or cleared between two reads cannot produce an answer no single moment supports. A network failure is never read as an answer. What the banner already knows, that new positions are blocked while repaying and closing stay open, shows at once; only the contact waits. The new lines are translated in every language that already translates the banner. This ships with the test list so that no network can be switched to the test list before the banner can describe it.

Base Sepolia was switched on 2026-10-07 by the owner running this script: the Diamond, which had no sanctions oracle until then, now screens against the admin's test list alone (no other list beneath it), and the deployment record carries its address. The admin, the Diamond and the treasury were checked unflagged afterwards. Still to do: a live drive with a dev wallet flagged and then cleared. The earlier plan to point Base Sepolia at Chainalysis's oracle (#1562) is dropped, since that oracle is retired. #946 still asks for a deploy phase that runs this step and a verify-time check that refuses a mainnet left without an oracle. Closes #2439 once the drive is done; until then, part of #2439.
