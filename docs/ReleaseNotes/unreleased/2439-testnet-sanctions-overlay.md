## Thread — a testnet sanctions test list, and one script that configures each chain's oracle (PR #2442)

Until now no script set a Diamond's sanctions oracle on any chain; the step was done by hand or not at all, and on Base Sepolia it had not been done. This adds a configure script that does it, by chain. On a mainnet it points the Diamond straight at Chainalysis's oracle for that chain, after checking that the contract at the known address really is Chainalysis's (it must report Chainalysis's owner and answer a screening read). Chainalysis does not use one address everywhere: Base has its own, and the script's table holds only addresses read on-chain on 7 October 2026. A mainnet with no known Chainalysis oracle is refused, not left quietly unscreened. On a Diamond owned by a timelock the script leaves the oracle as it was and prints the call to schedule. On a test network it still deploys and records the test list that call names, so the scheduled call never points at an address with nothing behind it. The configured oracle, its kind, and on a test network the Chainalysis oracle under it, are written into the chain's deployment record only once the Diamond actually uses that oracle. A dry run writes nothing, and the script follows the same local-only rule for skipping the deployment record as every other deploy step.

On a test network the script installs a new testnet-only contract, a sanctions test list. It reports an address as flagged when Chainalysis's oracle for that chain does, or when the network's admin has flagged it. Before this, no wallet we control could be flagged on a live deployment, because only Chainalysis can add to its list, so the paths that run only for a flagged wallet could not be exercised: the warning, the blocked actions, the close-outs that stay open, and the frozen-proceeds handling. The test list can add to Chainalysis's list but not remove from it. Every change is logged as an event. Ownership moves in two steps. The contract refuses to be created on any chain that is not on an explicit testnet list. When Chainalysis's oracle cannot be read, the test list passes that failure through unchanged, so a test network fails open and fails closed in exactly the places a mainnet would. A wallet the admin flagged stays flagged during such an outage. The test list can also say which of the two lists flagged a wallet, so that the app need not tell a user to contact Chainalysis about a flag Chainalysis never made. A second run reuses a recorded test list whose upstream is unchanged, so its flags are kept.

The app's flagged-wallet banner now names the list that actually flagged the wallet. Its last line used to tell every flagged user to contact Chainalysis, which would be false for a wallet only the test list flagged. It now asks the configured oracle. A wallet flagged only by Chainalysis, or on a mainnet, keeps the existing line. A wallet flagged only by the test list is told so, that Chainalysis has not flagged it, and that its recourse is the test network's operator. On a test network where Chainalysis publishes no oracle, the banner does not claim Chainalysis cleared the wallet: it says Chainalysis's list was not consulted because none exists there. A wallet on both lists is told that removing it from the test list would not clear Chainalysis's flag. When the test list's flag can be read but Chainalysis's side cannot, the banner says that. When the attribution cannot be read at all, or when at the moment it is read neither list flags the wallet any more, it names no contact and asks for a reload. Every attribution read is taken at one block, so a flag added or cleared between two reads cannot produce an answer no single moment supports, and the banner re-reads the attribution every 30 seconds while it is shown, so a list that lets go of a wallet stops being named. The oracle is treated as Chainalysis's own only when it answers that it has no test-list function. A network failure is not treated as that answer. What the banner already knows, that new positions are blocked while repaying and closing stay open, shows at once; only the contact waits for the attribution, so it is never shown with a guess. The script reuses a recorded test list only while the network's admin owns it and no ownership transfer is pending, since its owner decides who is flagged. The new lines are translated in every language that already translates the banner. This ships in the same change as the test list so that no network can be switched to the test list before the banner can describe it.

Not in this change: the switch itself. Base Sepolia is first pointed at Chainalysis's oracle directly (#1562). Running this script there afterwards replaces that with the test list and is a separate owner action, followed by a live drive with a dev wallet flagged and then cleared. #946 still asks for a deploy phase that runs this step and a verify-time check that refuses a mainnet left without an oracle. Closes #2439 once that drive is done; until then, part of #2439.
