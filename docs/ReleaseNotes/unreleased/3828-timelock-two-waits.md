## Thread — Governance timelock: two waits

The governance timelock now has two waits instead of one. Every queued change waits the standard wait, 7 days on a production chain. Only a short, fixed list of calls that restart something already built may run after the shorter restart wait of 48 hours: unpausing the platform, unpausing an asset, and the pause-epoch unpause. The timelock matches these calls exactly, with no value attached, and a batch counts only if every call in it is one of them.

An urgent fix can also run at 48 hours, but only when the Pauser Safe has approved that exact operation, by its id, before the governance Safe queues it. The approval is used up by that one operation and shortens nothing else; it can be withdrawn while unused, and it cannot be given to an operation already queued. An approval counts only while the account that gave it still holds the approver role and for three days after it was given, so revoking a rotated or compromised Pauser Safe voids every approval it left. Granting the role back to the same account later does not bring those approvals back. The proposer and the urgent approver can never be the same account, so a fast change always needs both Safes; this holds only while their signers are independent, which the runbook states as an off-chain requirement.

Both waits are fixed floors set at deploy and can only be raised, the standard wait never above 30 days, and the restart wait never above the standard one. The restart calls must reach the Diamond's pause facet (the facet behind its pause call); the deploy, the handover and the handover gate refuse a Diamond that routes them anywhere else. The timelock deploy, the handover and the handover gate refuse a production chain whose standard wait or its floor is under 7 days, or whose Pauser Safe does not hold the urgent-approver role. Testnet rehearsals can shorten both waits.

The launch proposal now asks the timelock which wait the launch needs and prints that delay (the standard one, since the launch is not a restart), so a proposal can no longer be printed with a delay the timelock would refuse. The governance queue reader looks for queued changes at both waits, and reports the standard wait beside the minimum. The incident recovery drills print the standard wait for their unpause batch, because it also restarts the cross-network contracts, and say that it runs at 48 hours only after the Pauser Safe approves it as urgent.

This is what the public upgrade-lock statement promises: a change that can move user funds waits 7 days, and only restarts and jointly approved urgent fixes are faster. The switch host's start call joins the restart list when that host is built (card #3824).
