## Thread — Only one keeper runs at a time, wherever it is hosted (PR #<n>)

The keeper can run on Cloudflare or on an always-on machine, and every copy signs with the same key. Until now, keeping a second copy from running at the same time was a matter of procedure alone. Now every tick first claims a single lease in the shared database under the copy's own name. While another copy holds the lease, the tick does nothing and logs which copy holds it and until when. A copy with no name, or one that cannot reach the database to claim the lease, does nothing either, because it cannot tell that it is the only one running.

A running copy renews the lease every minute, including minutes it skips because its previous tick is still running. A lease that stops being renewed lapses after ten minutes, so a machine that dies hands over to the next copy by itself. The Cloudflare copy is named "cloudflare-worker", and the machine install names each machine after its host name. The lease is a guard, not a fencing token, so the runbook's one-copy procedure still applies: the Worker's schedule stays empty while a machine runs, and an old machine is stopped before a new one starts.

The lease lives in the shared database for now, because that is the only one the machine runner can reach. It is keeper-only state, so it moves to the keeper's own database with the other keeper tables when that database lands.
